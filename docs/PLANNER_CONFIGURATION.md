# إعداد مخطط الموضوع المدعوم بالنموذج

الحالة الحالية: الموصل مفعل محليًا ومختبر حيًا. اختير `gpt-6-luna` للإصدار التجريبي بعد اجتيازه الحالات الأربع بدرجة كاملة وزمن أفضل من البديل الأقوى في الاختبار نفسه. يبقى المفتاح في `.env` غير المتتبع ولا يدخل Git أو صورة Docker.

## أوضاع التشغيل

### الوضع المنهجي الافتراضي

```env
MAZANN_PLANNER_PROVIDER=deterministic
```

لا يرسل بيانات إلى مزود نموذج، ويعيد خارطة `methodology_template` واضحة للمستخدم.

### OpenAI Responses API

```env
MAZANN_PLANNER_PROVIDER=openai
# Provide OPENAI_API_KEY and OPENAI_MODEL through the deployment secret manager.
```

لا يحدد المستودع نموذجًا افتراضيًا؛ يختار مالك المشروع النموذج المتاح لحسابه بعد مراجعة الجودة والكلفة. لا يوضع المفتاح في Git أو الواجهة أو الصورة.

يستخدم الموصل:

- `POST /v1/responses`؛
- Structured Outputs عبر `text.format` مع `strict: true`؛
- `store: false` لتعطيل تخزين الاستجابة لدى المزود؛
- مهلة مضبوطة؛
- fallback منهجي ظاهر عند timeout أو رفض أو خطأ شبكة أو مخرجات غير صالحة.

المراجع الرسمية:

- https://developers.openai.com/api/docs/guides/structured-outputs
- https://developers.openai.com/api/docs/guides/migrate-to-responses

## البيانات المرسلة

يرسل المخطط فقط:

- موضوع البحث ومقصده؛
- الجمهور والسياق والمدة؛
- هوية المنهجية ونسختها؛
- حالة التعليمات الحاكمة وبياناتها إن أدخلها المستخدم.

لا يرسل نصوص القرآن أو الحديث إلى المخطط، ولا يطلب منه إنشاءها. جمع الأدلة عملية لاحقة مستقلة عبر المصدر الإسلامي الرسمي.

## عقد الجودة

الموديل يعيد تحليل الموضوع، ومحاور من 3 إلى 5، وسؤالًا وسببًا ومنفعة ومتطلبات دليل لكل محور، وأسئلة استيضاح، وفحص تداخل وملاءمة ونطاق. بعد ذلك يتحقق الخادم من:

- عدد المحاور والأدوار المسموحة؛
- طول النصوص؛
- فئات الأدلة المسموحة؛
- توزيع الوقت؛
- بقاء المراجعة البشرية إلزامية.

إذا فشل أي شرط، لا تُعرض المخرجات الجزئية؛ يعود النظام إلى القالب المنهجي مع `planner_status.state = fallback`.

## بوابة التحقق الحي

لا نسجل الميزة بوصفها مكتملة قبل تنفيذ الحالات التالية بمفتاح مخصص للمشروع:

1. ثلاثة موضوعات مختلفة تنتج خططًا مختلفة جوهريًا؛
2. موضوع غامض ينتج سؤال استيضاح مناسبًا؛
3. جمهوران للموضوع نفسه ينتجان تكييفًا ظاهرًا؛
4. تعميم رسمي ينعكس في الخطة من دون معاملته دليلًا شرعيًا؛
5. انقطاع المزود يعيد fallback ظاهرًا؛
6. مراجعة بشرية للمحاور والأسئلة والمخاطر.

تُنفذ الحزمة القابلة للتكرار بالأمر:

```bash
npm run eval:planner
```

تحتوي `evaluation/planner-intelligence-cases.json` حاليًا على أربع حالات: قيمة أخلاقية، سياق شبابي رقمي، توجيه تنظيمي متحقق، وتكليف غامض. تقيس البوابة التخصيص، اختلاف المحاور، تنوع متطلبات الأدلة، تتبع التوجيه، طلب الاستيضاح، وعدم توليد نص مقدس أو إحالة منسوبة. نجاح البنية وحده لا يكفي، ووضع `methodology_template` لا يجتاز بوابة الذكاء مهما كانت درجته الهيكلية.

النتيجة الحية في 4 أكتوبر 2026: `passed`، بعدد `4/4` ومتوسط `1.00` على `gpt-6-luna`. استغرقت الحزمة المتسلسلة قرابة `79.56s`، واستغرق طلب واحد عبر API المحلي قرابة `14.95s`. هذه أرقام تشغيلية أولية وليست ضمان latency إنتاجي.

اجتاز `gpt-6.1-sol` الحالات نفسها أيضًا بدرجة كاملة، لكنه كان أبطأ في التشغيل المحلي. لذلك اختير Luna لتجربة العرض، مع إبقاء Sol خيار تصعيد إذا كشفت المراجعة البشرية فرقًا نوعيًا مهمًا.
